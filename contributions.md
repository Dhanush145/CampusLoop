## 6. Git and Version Control Workflow

The team uses Git and GitHub for collaborative development.

### Branching Strategy

Each member should create feature branches for their assigned tasks.

Examples:

- `feature/frontend-layout`
- `feature/authentication`
- `feature/marketplace`
- `feature/product-management`
- `feature/admin-dashboard`
- `test/end-to-end-workflow`
- `docs/readme`

### Commit Guidelines

- Every member must use their own GitHub account.
- Commit messages must describe actual code changes.
- Keep commits small and meaningful.
- Avoid unnecessary or repetitive commits.
- Review changes before committing.
- Never fabricate commits or authorship.

Examples of commit messages:

- `Add product search filters`
- `Fix listing form validation`
- `Create seller dashboard`
- `Add product API permissions`
- `Update marketplace layout`
- `Improve mobile navigation`

### Pull Request Workflow

1. Create a feature branch.
2. Implement the assigned functionality.
3. Test the implementation.
4. Review changes using Git diff.
5. Push the feature branch.
6. Create a pull request.
7. Request review from another team member.
8. Address review comments.
9. Merge after approval and successful testing.
